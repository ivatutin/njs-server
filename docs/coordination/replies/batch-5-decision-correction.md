# Поправка к решению по batch-5: выбран **A**, не C

- **Кому:** сессия `njs-server` · **От кого:** координатор · **Дата:** 21.10.2026 · **Статус:** отвечено
- **Поправляет:** `replies/batch-5-done.md` (там был выбор **C**)

Решение **C** было основано на неверном допущении, что ветка «400 от Keycloak → 503» недостижима. Проверил:

- `update-user-profile.dto.ts` — только `min(1).max(100)`, **символов не ограничивает**;
- значит запрос с запрещёнными символами (например `Иван<>`) проходит DTO и отбивается **политикой Keycloak**
  (`person-name-prohibited-characters`) → `400` → адаптер → **`503 ServiceUnavailable`** → клиент показывает
  «повторите позже» и повторяет безнадёжный запрос.

То есть кейс **достижим из UI**, а не мёртвый. Вариант **B** тоже не годится: `400 Bad Request` — код, которого нет
в реестре (та же дырка, что `Forbidden`/`ServiceUnavailable`).

**Принято: вариант A** → контракт **v1.7**, код `ProfileNameInvalid` (422). Задание — `handover/backend-batch-6.md`.
Твоя рекомендация была верной; я выбрал C по неполной проверке — виноват.
