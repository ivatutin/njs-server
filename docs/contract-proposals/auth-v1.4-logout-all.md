# Предложение к контракту Auth v1.x: v1.3 → v1.4 (выход на всех устройствах)

- **Класс изменения:** аддитивное (1 новый эндпоинт), новых кодов в реестр **не нужно** → `v1.3 → v1.4`
- **Запрашивает:** backend-сессия (`njs-server`), 2026-10-16
- **Статус:** **Proposed** — ждём решения координатора (форма эндпоинта, `X-Reauth-Token` да/нет)
- **Ломает ли фронт:** нет. Добавляется один эндпоинт, существующие не меняются; реестр кодов не трогаем

## Зачем

Пользователь должен уметь завершить **все** свои сессии — типовой сценарий после подозрения на кражу
токена/пароля, «выйти с чужого компьютера», после смены пароля на другом устройстве. В контракте такого нет:
`POST /auth/sign-out` гасит **только текущую** сессию (пер-токенный блоклист; отзыв по `sub` там сознательно
**не** вызывается — иначе выход на одном устройстве убивал бы все, ADR-0018). Механизм «убить всё» в коде
**уже реализован** и проверен живой приёмкой — `RevokeUserAccessUseCase` (ADR-0018): Keycloak `logoutAllSessions`
(3 попытки, шаг не best-effort) + метка `auth:sub-revoked:<sub>` в Redis. Нужен только контрактный вход.

**сверено с кодом:** `src/modules/auth/application/use-cases/revoke-user-access/revoke-user-access.use-case.ts:41-66`
(порядок «KC → метка», оба шага при ошибке дают `503` и метка не выставляется);
`src/modules/auth/application/use-cases/revoke-user-access/revoke-user-access.command.ts:2-7`
(значение `'logout-everywhere'` в типе причины **уже есть**);
`test/application/auth/sign-out.use-case.spec.ts:37-38` (`revokeUserTokens` при `sign-out` не вызывается — выход
на одном устройстве не убивает все).

## Что добавляется

### `POST /users/me/logout-all` — protected

```ts
// тела запроса нет; пользователь берётся из access-токена, как у остальных /users/me/*
204 → No Content
```

Семантика:

- гасит **все** сессии пользователя в Keycloak (refresh-токены всех устройств перестают работать) **и** ставит метку
  отзыва по `sub` — то есть все уже выданные access-токены тоже перестают приниматься (`401`);
- **текущий** access-токен тоже умирает: `204` означает «вы вышли везде, включая это устройство». Фронт после `204`
  обязан забыть токены и увести на вход; первый же запрос со старым токеном → `401`;
- **без `X-Reauth-Token`.** Обоснование: операция не может привести к захвату аккаунта (худшее — разлогин, а его
  пользователь и просит), а требование reauth создало бы **тупик для passwordless-пользователя** — reauth-токен
  неоткуда взять (тот же тупик I4, что у смены контакта). Если координатор всё же хочет reauth — это один декоратор
  (`@UseGuards(ReauthTokenGuard)`, как на `/users/me/password`), приму без возражений;
- **идемпотентно:** повторный вызов с живым токеном → тот же `204` (гасить уже погашенные сессии безопасно);
- **ошибка инфраструктуры → `503`**, новых кодов **нет** — та же семантика, что уже принята для отказов
  инфраструктуры (ADR-0015: «новых кодов нет, `503`»); в коде это `revoke-user-access.use-case.ts:50,62`;
- **не меняет** `POST /auth/sign-out` — выход на одном устройстве остаётся выходом на одном устройстве.

## Что нужно от других сторон

- **Фронт:** кнопка «Выйти на всех устройствах» в разделе безопасности; обработка `204` как «сессия окончена»
  (сброс токенов + уход на вход) и `503` как «не получилось, попробуйте позже» (сессия **не** тронута).
- **Контракт:** эндпоинт в инвентарь (16-й из «18»), версия `v1.4`, запись в changelog; реестр кодов **без изменений**.
- Принятие потребует уточнить ADR-0018: там в таблице стоит ««выйти везде» (если появится) — через Keycloak
  Account Console», а мы предлагаем свой эндпоинт (та же строка уже ссылается на `'logout-everywhere'`).

## Реализация (маленькая: без миграций, новых зависимостей и схем)

1. тонкий use case «выйти везде», вызывающий `RevokeUserAccessUseCase` с `reason='logout-everywhere'`;
2. метод в `AccountSecurityController` (`@Post('logout-all')`, `@HttpCode(204)`) — контроллер уже владеет всеми
   `/users/me/*` self-service операциями;
3. тесты: успех (`204` + вызов отзыва с нужной причиной), отказ Keycloak → `503` без метки, повтор — идемпотентен;
4. документы: ADR-0018 (уточнение), чек-лист; в `DEPLOYMENT` — только если понадобится runbook
   (по опыту отзыва: действий дежурного не требует).

## Вопросы координатору

1. Форма `POST /users/me/logout-all` → `204` — подтверждаешь? (ты её и предложил; альтернатива
   `DELETE /users/me/sessions` читается как «удалить список сессий», которого у нас нет).
2. Без `X-Reauth-Token` — согласен?
3. Развилка «отдавать ли ответ с телом»: **не предлагаю** `200 { revokedSessions: n }` — Keycloak не сообщает
   число погашенных сессий (в API адаптера это `client.logoutUser(keycloakId)` без ответа:
   `src/modules/auth/infrastructure/keycloak/keycloak-admin.adapter.ts:147-162`), а считать самим — выдумывать цифру.

## Итог рассмотрения координатором (16.10.2026)

**Принято целиком, контракт поднят до v1.4** — ответ координатора: `docs/auth/sessions/njs-server/replies/logout-all-proposal.md`.

- форма `POST /users/me/logout-all` → `204` — подтверждена;
- **без `X-Reauth-Token`** — согласовано (обоснование принято: операция не даёт захвата аккаунта, а reauth создал бы
  тупик для passwordless-пользователей, I4); отдельный rate-limit не нужен — хватает глобального throttler'а;
- **без счётчика в теле** — согласовано («цифру не выдумываем»); фронту отдельно запрещены любые «вышли N сессий»;
- контракт обновлён координатором (`docs/auth/contract.md` → v1.4 + перегенерирован `contract.sha256`), зеркала сессий
  синхронизируются перекопированием.

**Реализовано и принято живьём** в этой же сессии: код `logout-all` (`LogoutAllUseCase` → `RevokeUserAccessUseCase`,
`reason='logout-everywhere'`), тесты 5 кейсов, ADR-0018 уточнён, чек-лист обновлён; приёмка — `204` → `401` (тот же токен)
→ `401` (второе устройство) → `401` (refresh) → повтор `204` → свежий вход `200`. Отчёт о реализации —
`docs/auth/sessions/njs-server/questions/logout-all-implemented.md`, о приёмке —
`docs/auth/sessions/njs-server/questions/logout-all-acceptance.md`.
